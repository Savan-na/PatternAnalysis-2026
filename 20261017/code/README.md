## Current documentation entry points — 20 October 2026

Use [the methods index](docs/README.md) for protocol status, frozen documents,
and historical command examples. The current experiment is the [v4 A0/A1
paired protocol](docs/V4_Paired_Training_ZH.md), submitted as jobs 679166/679167;
both jobs were last confirmed running, and completion is not yet verified. The v2 and v3 implementations supplement the
three original model files described below. Historical configurations and
hash-pinned protocol snapshots remain at their original paths.

This folder contains the implementation and prespecified methods for the
independent HipMRI study. The package `hipmri_rewrite` defines data validation,
geometry-preserving preprocessing, PyTorch models, losses, inference,
overlap/boundary metrics, and pretraining audit/profile commands. `config/`
contains the fixed patient split; `tests/` contains synthetic contract tests.

The available model implementations live in
`hipmri_rewrite/models/baseline_2d.py`, `baseline_3d.py`, and
`improved_3d.py`, supplemented by `hipmri_rewrite/improved_v2.py` and
`hipmri_rewrite/improved_v3.py`. V4 reuses the v3 architecture and changes its
training recipe via `tools/train_v4_cohort.py`; it is not another network file.
The original arms' identity records are in
`config/arms/<arm_id>/arm.json`. The frozen training configurations are
`config/g5_controlled_training_frozen.json` for the two primary 3D arms and
`config/g5_2d_training_frozen.json` for the supplementary 2D arm. All three
runs completed; the 3D runs continued from 40 to 50 epochs without changing
their frozen data, model or optimizer settings.

Run from this `code` directory in the existing Python 3.11 `torch` environment:

```text
python -B -m unittest discover -s tests -v
```

The study hypotheses and evaluation rules are in
[`docs/STUDY_PROTOCOL.md`](docs/STUDY_PROTOCOL.md). The provenance of each
architectural or data decision is in
the [source-decision history](docs/METHODS_EXECUTION_HISTORY.md#sources). Real-data and GPU
gates are in the [execution history](docs/METHODS_EXECUTION_HISTORY.md#evidence), while commands for the
student's two separate terminals are in
the [historical Rangpur handoff](docs/METHODS_EXECUTION_HISTORY.md#commands).

The source-only transfer ZIP is generated by `python tools/package_transfer.py`
and stored as a new `transfer/source_current.zip` (or explicit `--output`).
It refuses overwrites and excludes nested transfer ZIPs, raw logs, medical-derived results,
weights, NIfTI data, and the generated project map. Frozen v4 packaging likewise
refuses to overwrite its existing identity or directory analysis. Regenerate the map on
Rangpur after unpacking. The study is an annotation-assistant prototype, not
a source of clinical contours.

The three G1 review tools render selected raw overlays, targeted Bladder
component views, and all-patient contact sheets. Their local figure groups are
`results/data_analysis/representative_alignment_review/`, `g1_bladder_review/`, and
`g1_patient_screen/` respectively. The tools accept an explicit output
directory and leave the original MRI/Mask files unchanged.

`tools/summarize_g2_train_audit.py` checks the full G1 audit hash and frozen
split, then exports Train-only class, volume, patient, intensity and spatial
statistics plus four SVG plots. It uses the local `comp2011` environment's
Matplotlib; no raw NIfTI is required for this first G2 summary.
`tools/audit_g2_train_slices.py` ran on Rangpur CPU. It decodes only
Train pairs and checks their class counts against the complete G1 audit before
exporting axial-slice coverage and nonzero MRI intensity histograms. Use
`--limit 2` for a smoke run with a separate output directory.
`tools/summarize_g2_slice_detail.py` verifies the transferred full-run CSV
hashes and reconciles every case with G1 before generating local slice and
pooled-intensity figures. It does not interpret slice presence as patch exposure.
`tools/audit_g3_existing_pipeline.py` audits the existing Train-only path from
raw volumes through factor-two downsampling, nonzero Z-score and whole-volume
model arrays. It checks class, physical-volume and axial-slice preservation,
normalization and padding without defining a new sampler.
`tools/summarize_g3_pipeline.py` verifies the complete G1 and G3 JSON hashes,
reconciles all 143 raw case counts, and exports a Train-only organ-preservation
table and figure into `results/data_analysis/preprocessing_validation/`.
`tools/audit_g3_candidate_sampling.py` uses the frozen
`config/g3_patch_audit.json` to simulate uniform and organ-aware crops on the
verified Train grid. This is an exposure audit for a possible future policy;
it is not wired into model training.
`tools/summarize_g3_candidate_sampling.py` verifies the returned full-cohort
CSV and manifest against Rangpur SHA-256 values and the G3 case grids before
producing local exposure tables and a comparison figure under
`results/data_analysis/preprocessing_validation/`.

`hipmri_rewrite/sampling.py` prepares paired Train-only 3D patches with one
scan per patient per epoch and records label exposure from the model-ready
Mask. `tools/audit_g4_patient_sampling.py` dry-runs the uniform and organ-aware
candidate policies on Rangpur CPU, without training; its measured tensor
stream was verified across 26 Train patients. The local
`tools/summarize_g4_patient_sampling.py` checks each returned record and
produces a patient-balanced exposure table and figure under
`results/data_analysis/patient_balanced_sampling/`. Uniform crops are the reference
for the first controlled comparison; organ-aware crops remain a targeted
follow-up candidate until actual batch logs and Validation justify them.

`tools/probe_g5_patch_gpu.py` is a Train-only CUDA feasibility gate for the
two primary 3D arms. It builds a real, uniform-crop batch through the verified
data path, checks the shared provisional CE+Dice forward/backward objective,
and records gradient and memory results. It makes no optimizer step and saves
no checkpoint; its outcome informs a later frozen training configuration.
`tools/tiny_overfit_g5.py` then makes a bounded number of optimizer steps on
two fixed Train patches containing Rectum and Prostate. It records fixed-batch
loss, per-class Dice/recall and prediction counts for both 3D arms, and saves
no model weights. This is a learning-correctness gate, not a Validation result.

`tools/submit_g5_40.sh` submitted the two frozen 3D training arms as Slurm
jobs 672954 and 672955 after recovery test 672953. The trainer records an
atomic latest-batch checkpoint and one durable checkpoint plus detailed JSON
per completed epoch. Submission and queue estimates are not training results.
`tools/audit_g5_2d_sampling.py` compares uniform and target-aware 2D crops
on one Train visit per patient on a CPU node. Its exposure results must be
reviewed before selecting the supplementary 2D training policy. That audit
completed on 26 Train patients and supported `patient_organ_aware_2d`.
`config/g5_2d_training_frozen.json` records its own Train-derived class weights,
40-epoch budget, and Validation selection rule. `tools/train_g5_2d.py` is the
separate checkpointed runner; its Validation uses whole-volume slice-wise
inference, and it never reads Test arrays during training.
`tools/submit_g5_2d.sh` verifies transferred files and gates the A100 job on
a CPU recovery and frozen-config check.

`tools/summarize_g5_validation.py` reads the two completed 3D runs' local
epoch JSON records and independently checks each Train and Validation summary.
The current six-class figures and training trajectories are produced by
`tools/summarize_all_class_review.py`. The legacy three-organ plots are retired.

`tools/submit_g5_extend_50.sh` continued both 3D runs with strict resume
checks. `tools/review_g5_validation_failures.py` generated selected Validation
overlays. `tools/evaluate_g6_test.py` evaluated the two selected checkpoints
once on the held-out Test set; `tools/review_g6_test_cases.py` reproduced
selected case confusion matrices before rendering descriptive Test overlays.
Local summaries and interpretation are in the formal research report.

`tools/summarize_all_class_review.py` verifies the selected G5 records and
one-time G6 result, then draws six-class comparisons, three-arm trajectories, a foreground HD95
comparison and a descriptive Test failure review. It also exports per-case,
per-class Test metrics to the existing comparison table folder. The bounded
2D continuation helper is `tools/submit_g5_2d_extend_50.sh`; it resumes the
same frozen run without changing data, weights or optimizer settings.
`tools/review_g6_body_boundaries.py` is a staged descriptive GPU review of
three high-HD95 Test cases. It verifies the original Test confusion matrices
before drawing Body boundaries; its output has been reviewed locally.
`tools/audit_g5_validation_body.py` applies the same fixed checkpoints to all
38 Validation volumes, reproduces their saved confusion matrices, measures
Body surface distances and draws the worst cases by patient. Its result will
inform a Train/Validation-only intervention decision.
`tools/audit_g5_train_patch_geometry.py` reconstructs the exact frozen 3D
uniform crop origins from Train shapes, config and both arms' epoch schedules.
It records how often outer volume faces and corners entered training crops,
without reading MRI data or using Validation/Test labels.
`tools/audit_g5_aux_logits_validation.py` compares the selected Improved 3D
summed logits with its main head alone on the same Validation volumes. This
read-only diagnostic checks whether the auxiliary outputs contribute to the
Body false positives; the main head was not trained as a separate model.
`tools/summarize_g5_body_review.py` verifies the transferred Validation
audit against the selected epoch records and draws patient-level Body errors.

`hipmri_rewrite/sampling_edges.py` implements the separate G7 candidate:
preserve draws 0–8 and replace draw 9 with a deterministic corner crop. It
requires at least 5% nonzero model-input MRI and 128 nonzero GT Background
voxels in the outer 8-voxel shell at least 20 mm from GT Body. It tries up to
64 origins across eight corners, then falls back to the original uniform
draw. These proposed thresholds are for the Train-only audit.
`tools/audit_g7_edge_sampling.py` decodes each scheduled Train volume once,
replays up to 50 G5 epochs, and checks every full baseline epoch's measured
label exposure against its saved training record. Its paired CSV and manifest
report spatial coverage, all six class counts, nonzero intensity, fallbacks,
and the predeclared exposure gates. `tools/submit_g7_edge_audit.sh smoke`
submits a two-patient/two-epoch CPU check; `full` requires a successful smoke
with unchanged candidate sources before submitting the 143-volume audit.
Neither command submits model training. Transfer and execution steps are in
[`docs/RANGPUR_COMMANDS.md`](docs/METHODS_EXECUTION_HISTORY.md#commands).
The full CPU audit completed as job 676249. Its downloaded CSV and manifest
are independently reconciled by `tools/summarize_g7_edge_sampling.py`, which
exports six-class exposure and normalized crop-origin figures to
`results/data_analysis/boundary_sampling_audit/`. Passing its provisional exposure
gates does not establish a model-quality benefit.
