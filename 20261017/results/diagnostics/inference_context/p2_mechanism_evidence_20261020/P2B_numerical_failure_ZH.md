# P2B 数值正控失败：保留结果，暂停机制归因

## 实际观察

Rangpur 作业 **677509** 在 12 秒后以 `1:0` 退出，五项测试通过，但首例 `K018_Week4` 的整卷自身统计回放不满足预设阈值。以下数值来自用户粘贴的远端失败 JSON，本轮尚未下载原文件核对 SHA。

| 指标 | 预设上限 | 远端报告值 |
|---|---:|---:|
| 所有 head 最大绝对 logit 差 | 0.001 | 0.0240402222 |
| padded grid argmax 不一致比例 | 0.00001 | 0.0000295639038 |

既有 P2 记录显示该例网格为 128×128×64，无额外 padding；报告比例对应 **31 个标签变化**。31 个变化相对总数很少，但不能因此越过事先定义的两个正控上限。

程序在取得合格数值对照前停止，没有完成 P2B 的统计回放机制比较、置信度或过滤诊断。原 P2 的整卷/滑窗观察仍然保留；本次失败既不证明 InstanceNorm 导致远处误检，也不否定归一化统计可能参与。

## 待检验的数值解释

历史回放使用独立的 `torch.var_mean`，再逐步执行减均值、rsqrt、乘 affine、加 bias；原 InstanceNorm 可能采用不同的后端统计归约及融合算术。这些数学等价表达在 FP32 深网络中不保证逐位等价。还需排除原生前向重复自身的数值变化。

当前不能只凭最终 0.02404 就确定误差来自统计量、融合算术还是其他执行细节，也不能把该解释写成已查明的模型缺陷。

## 最小下一项：只做数值定位

新增 `code/tools/audit_p2b_replay_numerics.py`，单例、固定 Improved 第 50 轮权重、整卷输入。四个固定实现对照为：

1. 原生前向重复，判断基线是否稳定。
2. 原历史手写回放，检查能否复现失败量级。
3. 后端保存的 mean/invstd 配合融合 affine 算术。
4. 后端保存的 mean/invstd 配合原生 elementwise 归一化算子（若 CUDA 后端可用）。

同时逐层比较原 InstanceNorm、等价 B=1 BatchNorm 后端结果、独立统计量及各回放表达。它们是数值实现校验，不是按分割效果扫描网络、窗口或阈值。私有 ATen 算子仅用于已记录 PyTorch 版本的诊断，不能无验证移入正式推理。

旧阈值和原脚本均不改变；本脚本只报告每种实现是否满足旧正控，不自动继续滑窗实验。检查模型参数/缓冲区哈希，原生预测必须复现 P2。新结果写入 `logs/validation/inference_context/p2b_numerical_audit_20261020/audit.json`，不覆盖失败目录或日志。建议只运行一次、GPU 作业预算 5 分钟，失败后先分析记录。

本地 CPU 算子/融合 affine 自检已通过；这不证明 CUDA 等价性。真实数值定位作业尚未提交。
